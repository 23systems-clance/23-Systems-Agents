23 Systems Workforce Complete Operating Guide

Everything you need to deploy, operate, and extend your autonomous AI agent. Covers architecture, job lifecycle, all specialties, and administration.

System Overview

23 Systems Workforce is an autonomous AI agent powered by the 23wf npm package. It accepts tasks through a web chat UI, Telegram, cron schedules, webhooks, or direct API calls, and executes them using LLM-driven Docker containers that commit results as pull requests.

What 23 Systems Workforce Can Do
  • Execute autonomous coding and research tasks via AI agents (Pi or Claude Code)
  • Search the web, scrape pages, and extract content
  • Interact with Google NotebookLM to create podcasts, reports, quizzes, and more
  • Automate browser interactions via Chrome DevTools Protocol
  • Generate images and videos via KIE AI
  • Manage Google Drive files and create Google Docs
  • Run scheduled tasks on cron and respond to webhook events
  • Generate branded SOP documents from templates

Architecture

23 Systems Workforce uses a two-layer architecture separating orchestration from execution.

Layer 1: Event Handler

A Next.js 15 server that handles all incoming requests and orchestrates job creation.

  • Web UI for chat, job management, notifications, and settings
  • Telegram bot integration for mobile access
  • Cron scheduler (node-cron) for timed tasks
  • Webhook receiver for event-driven triggers
  • SQLite database (Drizzle ORM) for users, chats, messages, and settings
  • NextAuth v5 for session management (email/password, JWT cookies)
Layer 2: Docker Agent

An ephemeral container spun up by GitHub Actions for each job.

  • Runs the Pi coding agent or Claude Code as the LLM backend
  • Clones the job branch, reads the task prompt, executes autonomously
  • Commits results and opens a pull request
  • Container is destroyed after job completes
Job Lifecycle
  1. Job created — Event handler receives a task via chat, cron, trigger, or API and calls createJob()
  2. Branch pushed — A job/<uuid> branch is created on GitHub with logs/<uuid>/job.md containing the task prompt
  3. Workflow triggers — GitHub Actions run-job.yml fires on the new branch
  4. Container runs — Docker agent clones the branch, loads personality from config/SOUL.md, executes the task with all active specialties available
  5. PR created — Agent commits results and opens a pull request
  6. Auto-merge — auto-merge.yml squash-merges the PR if all changed files fall within ALLOWED_PATHS (default: /logs)
  7. Notification — Results are sent back to the web UI and Telegram
Note: Each job gets its own isolated branch and container. Jobs cannot interfere with each other or with the main branch unless auto-merge conditions are met.

First-Time Setup

Prerequisites
  • Node.js 22+
  • A GitHub repository with Actions enabled
  • A GitHub Personal Access Token (PAT) with repo permissions
  • An Anthropic API key (or OpenAI/Google API key)
  • Docker (for local development with docker-compose)
Installation Steps
  1. Clone your 23 Systems Workforce repository and run npm install
  2. Run npx 23wf init to scaffold the project structure
  3. Copy .env.example to .env and fill in required values: 
    APP_URL=https://your-domain.com
AUTH_SECRET=<auto-generated>
GH_TOKEN=ghp_...
GH_OWNER=your-github-username
GH_REPO=your-repo-name
ANTHROPIC_API_KEY=sk-ant-...
  4. Start the event handler: npm run dev (local) or docker compose up -d (production)
  5. Visit your APP_URL and create your admin account on first login
  6. Generate an API key in Settings > Secrets for programmatic access
Optional: Telegram Setup
  1. Create a bot with @BotFather on Telegram and get the bot token
  2. Add TELEGRAM_BOT_TOKEN and TELEGRAM_CHAT_ID to .env
  3. Register the webhook: POST /api/telegram/register with your API key
Tip: The first user to visit the login page becomes the admin. Set up your account immediately after deployment.

Creating Jobs

Jobs are the core unit of work in 23 Systems Workforce. Every job runs in an isolated Docker container with its own Git branch.

Three Action Types
TypeUses LLMRuntimeCostUse Case
AgentYesMinutes to hoursLLM API + ActionsTasks requiring thinking, reasoning, coding
CommandNoMillisecondsFreeShell scripts, file operations
WebhookNoMillisecondsFreeExternal API calls, forwarding
Via Web Chat

Simply type your task in the chat interface. The event handler's LLM will determine if it should create an agent job or respond conversationally. Be specific about what you want the agent to do.

Example prompt: "Search the web for the latest AI regulation news, create a NotebookLM notebook with the top 5 articles, and generate a briefing document."
Via API
curl -X POST https://your-domain.com/api/create-job \
  -H "x-api-key: 23wf_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{"job": "Analyze the logs and write a summary report"}'
Writing Good Job Prompts
  • Be specific about the desired output — "generate a podcast" vs "create something"
  • Reference specialties by name when needed — "Use the brave-search specialty to find..."
  • Include install steps for specialties that need them — "Run skills/notebooklm/install.sh first"
  • Specify where to save outputs — "Save the report to logs/"
  • Break large tasks into sequential steps in your prompt

Cron Jobs

Scheduled tasks defined in config/CRONS.json. Loaded at server startup by node-cron.

Configuration Format
{
  "name": "Daily Research Digest",
  "schedule": "0 9 * * *",
  "type": "agent",
  "job": "Use brave-search to find today's top AI news...",
  "enabled": true
}
FieldRequiredDescription
nameYesDisplay name for the job
scheduleYesCron expression (e.g., 0 9 * * * = daily 9am)
typeNoagent (default), command, or webhook
jobFor agentTask prompt sent to the LLM
commandFor commandShell command (runs in cron/ directory)
urlFor webhookTarget URL for HTTP request
enabledNoSet false to disable (default: true)
llm_providerNoOverride LLM provider for this cron only
llm_modelNoOverride LLM model for this cron only
Common Cron Expressions
ExpressionMeaning
*/5 * * * *Every 5 minutes
0 * * * *Every hour
0 9 * * *Daily at 9:00 AM
0 9 * * 1-5Weekdays at 9:00 AM
0 9 * * 1Every Monday at 9:00 AM
0 0 1 * *First of each month at midnight

Webhook Triggers

Event-driven actions defined in config/TRIGGERS.json. Triggers fire on POST requests to watched paths.

Configuration Format
{
  "name": "GitHub Push Review",
  "watch_path": "/webhook/github-push",
  "enabled": true,
  "actions": [
    {
      "type": "agent",
      "job": "Review the push to {{body.ref}}: {{body.head_commit.message}}"
    }
  ]
}
Template Tokens

Use these placeholders in job and command strings — they resolve to incoming request data:

TokenResolves To
{{body}}Entire request body as JSON
{{body.field}}Nested field from request body
{{query}}All query parameters as JSON
{{query.field}}Specific query parameter
{{headers}}All request headers as JSON
{{headers.field}}Specific request header

Specialty: Brave Search

Web search and content extraction using the official Brave Search API. No browser required — lightweight and fast.

Setup
  1. Create an account at api-dashboard.search.brave.com
  2. Create a "Free AI" subscription (credit card required, not charged)
  3. Create an API key for the subscription
  4. Store the key: npx 23wf set-agent-llm-secret BRAVE_API_KEY "your-key"
  5. Install dependencies: cd skills/brave-search && npm install
Usage
# Basic search (5 results)
skills/brave-search/search.js "query"

# More results with page content
skills/brave-search/search.js "query" -n 10 --content

# Filter by freshness
skills/brave-search/search.js "query" --freshness pw    # past week
skills/brave-search/search.js "query" --freshness pm    # past month

# Filter by country
skills/brave-search/search.js "query" --country DE

# Extract content from a specific URL
skills/brave-search/content.js https://example.com/article
OptionDescriptionDefault
-n <num>Number of results5 (max 20)
--contentInclude page content as markdownOff
--country <code>Two-letter country codeUS
--freshness <period>Time filter: pd, pw, pm, py, or date rangeAll time

Specialty: NotebookLM

Full programmatic access to Google NotebookLM — create notebooks, add sources, chat with them, and generate artifacts like audio podcasts, videos, reports, quizzes, slide decks, infographics, and more.

Setup
  1. Install locally: pipx install notebooklm-py
  2. Install Playwright for browser login: pipx inject notebooklm-py playwright
  3. Install Chromium: find the Playwright binary in the pipx venv and run playwright install chromium
  4. Authenticate: notebooklm login (opens browser for Google sign-in)
  5. Verify: notebooklm auth check --test
  6. Store credential for Docker agent: npx 23wf set-agent-llm-secret NOTEBOOKLM_AUTH_JSON < ~/.notebooklm/storage_state.json
Important: Always start job prompts with skills/notebooklm/install.sh — this installs Python and the CLI in the Docker container.
Core Workflows

Create a notebook and add sources:

notebooklm create "Research Topic"
notebooklm use <notebook_id>
notebooklm source add "https://example.com/article"
notebooklm source add "https://youtube.com/watch?v=xyz"
notebooklm source add ./document.pdf

Ask questions (source-grounded Q&A):

notebooklm ask "What are the key themes?"
notebooklm ask "Compare viewpoints" -s <src1> -s <src2>
notebooklm ask "Explain X" --save-as-note

Generate audio podcast:

notebooklm generate audio --format deep-dive --wait
notebooklm download audio ./podcast.mp3

Generate other artifacts:

# Report
notebooklm generate report --format briefing-doc --wait
notebooklm download report ./report.md

# Slide deck
notebooklm generate slide-deck --wait
notebooklm download slide-deck ./slides.pptx --format pptx

# Quiz
notebooklm generate quiz --difficulty hard --wait
notebooklm download quiz ./quiz.md --format markdown

# Video
notebooklm generate video --format explainer --style whiteboard --wait
notebooklm download video ./explainer.mp4

# Infographic
notebooklm generate infographic --orientation landscape --wait
notebooklm download infographic ./info.png

# Mind map / Data table
notebooklm generate mind-map
notebooklm download mind-map ./map.json
notebooklm generate data-table "compare concepts" --wait
notebooklm download data-table ./data.csv

Managing Secrets
# Set a secret (creates GitHub secret with AGENT_LLM_ prefix)
npx 23wf set-agent-llm-secret BRAVE_API_KEY "your-key"

# Set a multi-line secret (pipe via stdin)
npx 23wf set-agent-llm-secret GOOGLE_CREDENTIALS < credentials.json

skills/llm-secrets/llm-secrets.js

echo $BRAVE_API_KEY
Never commit secrets. Always use set-agent-llm-secret for credentials. The .env file is gitignored and should only be used for local development.

Troubleshooting

ProblemCauseSolution
Job never starts GitHub Actions runner not available Check /runners page. Verify GH_TOKEN has workflow permissions. Check GitHub Actions is enabled on the repo.
Job fails immediately Missing secrets or invalid config Check the job's GitHub Actions log. Verify required AGENT_* secrets exist.
PR not auto-merging Changed files outside ALLOWED_PATHS Update ALLOWED_PATHS repo variable or merge manually. Default only allows /logs.
NotebookLM auth fails Google cookies expired Re-run notebooklm login locally and update the NOTEBOOKLM_AUTH_JSON secret.
Specialty not found in job Specialty not activated Verify symlink exists in skills/active/. Run ls -la skills/active/.
Telegram not responding Webhook not registered POST to /api/telegram/register with API key. Verify APP_URL is publicly accessible.
Chat LLM errors Invalid or missing API key Check LLM_PROVIDER and corresponding API key in .env. Verify the key is valid.
Database locked Multiple processes writing Restart the event handler. SQLite handles concurrent reads but only one writer.
Docker container fails Image not found or build error Check JOB_IMAGE_URL and EVENT_HANDLER_IMAGE_URL repo variables. Verify GHCR access.
Cron job not firing Invalid schedule or disabled Verify cron expression in CRONS.json. Check "enabled" is not false. Restart server after editing.

Technical Documentation System

23 Systems maintains a structured technical documentation system in docs/ designed to reduce AI agent context window usage by 70-90%. Instead of exploring dozens of source files, Claude Code reads a focused reference doc.

How It Works
  1. Index-first routing — docs/INDEX.md is a master table of contents. AI agents read the index (~30 lines), identify which doc is relevant, and read only that one doc.
  2. Self-contained docs — Each doc covers one domain (database, specialties, deployment, etc.) and can be understood independently without reading other docs.
  3. CLAUDE.md integration — A reference in CLAUDE.md directs agents to check docs/INDEX.md before exploring the codebase.
  4. Constitution enforcement — .specify/CONSTITUTION.md requires documentation updates when architecture changes.
