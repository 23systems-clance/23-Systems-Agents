RESEARCH ANALYSIS
Agentic Engineering Case Study

Stripe Minions

How Stripe built an in-house fleet of coding agents that generate 1,300+ production PRs per week — and what it means for the future of software engineering.
1

Executive Summary

Stripe's Minions are a fleet of homegrown, fully autonomous coding agents that handle end-to-end code generation — from task intake to PR creation — without human supervision during execution. They now produce over 1,300 merged pull requests per week, all reviewed by human engineers before merging. Built on a fork of Block's open-source Goose agent and running inside isolated cloud-based development environments called "Devboxes," Minions represent the most mature enterprise deployment of agentic coding at scale made public to date.

What makes Minions significant is not just the volume of code they produce, but the engineering philosophy behind them: deterministic workflows (Blueprints) interleaved with agentic decision-making, a curated ecosystem of 500+ MCP tools, and a conviction that investments in human developer infrastructure pay compounding dividends when agents inherit that same infrastructure.

Key takeaway: Stripe proves that production-grade agentic coding requires specialization, isolation, and a hybrid architecture that constrains agent freedom to well-defined subtasks — not unbounded autonomy.
2

The Problem

Off-the-shelf coding assistants like Copilot, Cursor, and Claude Code are powerful for general-purpose development. But Stripe's codebase presents challenges that make generic tools insufficient.

Codebase Complexity
  • Hundreds of millions of lines of code — primarily Ruby with Sorbet typing, along with proprietary libraries and frameworks that no public LLM has been trained on
  • Deep institutional knowledge required — "Humans must build sophisticated mental models to make effective changes in our repos"
  • Proprietary tooling — internal systems for feature flags, documentation, ticketing, and deployment that have no public equivalents
Operational Stakes
  • Over $1 trillion in annual payment volume — bugs in payment processing code have immediate, measurable financial consequences
  • Regulatory and compliance obligations — PCI DSS, financial regulations, and audit requirements demand rigorous change management
  • Zero-downtime expectations — serving millions of businesses means no room for agent-introduced regressions
Why not use off-the-shelf? Generic coding agents lack context on Stripe's proprietary stack, cannot access internal tools, and provide no guarantees about the safety or compliance of generated code in a payments-critical environment.

Architecture Overview

The Minions system follows a layered architecture: multiple entry points feed tasks into isolated execution environments, where a customized agent harness orchestrates work through hybrid deterministic-agentic workflows, iterates against CI, and produces review-ready pull requests.

A feature branch with CI-passing code is opened as a pull request. A human engineer reviews and merges — always.

Key Components Deep Dive

Devboxes

Devboxes are the foundational infrastructure that makes unattended agent execution possible. Each one is a standardized, disposable AWS EC2 instance that provides complete isolation for agent work.

Infrastructure
Hot Provisioning
~10 seconds
Pre-warmed pools of EC2 instances with cloned repositories, warmed caches, and running code generation services. No cold-start penalty.
Infrastructure
Full Isolation
Zero prod access
Each agent gets its own machine with no production access. Enables parallelization, predictability, and safe unattended execution.

The key insight: Devboxes were originally built for human developers. The investment in fast, reproducible, isolated development environments translated directly into agent infrastructure. Agents inherit the same tooling, dependencies, and environment that human engineers use daily.

Agent Harness (Goose Fork)

Stripe's agent loop is a customized fork of Block's open-source Goose coding agent, modified to integrate with Stripe's internal LLM infrastructure and to support fully unattended execution.

  • Fully unattended — no interruptibility features, no confirmation prompts, no human-in-the-loop during execution
  • Full permissions — agents have unrestricted access within their Devbox sandbox (but no production access)
  • Deterministic interleaving — the harness alternates between free-form agent nodes and deterministic operations (git, lint, test)
  • Custom LLM integration — connected to Stripe's own model infrastructure rather than direct API calls
Why fork Goose? Consumer coding tools are designed for interactive use with human supervision. Unattended agents need different primitives: no pause/resume, no approval gates, and tight integration with enterprise infrastructure.
Blueprints (Core Innovation)

Blueprints are Stripe's most distinctive contribution — hybrid workflows that combine deterministic code nodes with agentic decision-making nodes, structured as a state machine.

"A state machine that intermixes deterministic code nodes and free-flowing agent nodes."
Node TypeDescriptionExampleWhy It Matters
Deterministic Fixed code operations that always produce the same output for a given input Git checkout, linting, file scaffolding, test selection No LLM tokens consumed; predictable; fast
Agentic LLM-powered nodes with freedom to reason, plan, and generate code Writing implementation logic, diagnosing test failures, code review prep Handles ambiguity and novel problems

Benefits of the Blueprint pattern:

  • Reduced token consumption — deterministic tasks don't burn LLM calls
  • Constrained agent freedom — each agentic node has a scoped subtask, not free reign over the entire problem
  • Lower CI costs — deterministic validation catches errors before expensive test runs
  • Team-specific customizations — teams can author Blueprints tailored to their domain (e.g., API migrations, schema changes, test generation)
Context Engineering: Rule Files

Minions use Cursor's .cursorrules format for directory-scoped guidance. These rule files provide the agent with context about conventions, patterns, and constraints specific to each part of the codebase.

  • Same rules, everywhere — the exact same rule files are synchronized across Minions, Cursor, and Claude Code
  • Directory-scoped — different parts of the monorepo can have different conventions without global config pollution
  • Human-maintained — engineers write and update rule files as they would documentation, ensuring agents always have current guidance
Reuse pattern: By adopting the same rule file format across all tools (human and agent), Stripe ensures that improvements to documentation benefit both human developers and automated agents simultaneously.
MCP Toolshed

Toolshed is Stripe's internal MCP (Model Context Protocol) server hosting approximately 500 tools that span internal systems and SaaS integrations. Agents connect to Toolshed to interact with Stripe's internal ecosystem.

  • Curated tool subsets per task — not all 500 tools are available for every task; tool sets are scoped to relevance
  • Security controls — destructive actions are gated; agents cannot delete production resources or bypass safety checks
  • Spanning internal + external — tools cover everything from internal feature flags and docs platforms to external SaaS APIs
CI / Iteration Loop

The iteration loop is a carefully constrained feedback cycle designed to catch and fix errors without burning excessive compute.

StageExecutionDurationDetails
1. Local Lint Deterministic (Blueprint node) < 5 seconds Heuristic-based linting catches formatting, typing, and structural issues
2. CI Test Run Selective from test battery Minutes Relevant subset selected from 3+ million available tests
3. Autofix Deterministic Seconds Tests with known autofixes apply corrections automatically
4. Second Iteration Agentic Minutes If failures remain, agent gets one more attempt to diagnose and fix
5. Escalation Human — If second iteration fails, task escalates to a human engineer
Two-round limit: Stripe caps CI iterations at two rounds. This prevents runaway compute costs and recognizes that some tasks genuinely require human judgment. The agent admits what it cannot solve rather than flailing.

Design Principles

Beneath the technical architecture, Stripe's approach rests on a set of philosophical pillars that other engineering organizations can learn from regardless of their scale.

Human Infrastructure Pays Dividends for Agents
"Investments in human developer productivity over time have returned to pay dividends in the world of agents." Devboxes, rule files, linting, CI — all built for humans — became the foundation for agent execution. The lesson: build excellent developer infrastructure and agents will inherit it.
Code + Agents > Either Alone
Blueprints represent the conviction that mixing deterministic code with agentic reasoning produces better outcomes than pure code automation or pure LLM generation. Deterministic nodes handle what code does best (speed, predictability). Agentic nodes handle what LLMs do best (ambiguity, reasoning).
Specialization Over Generality
Rather than deploying one general-purpose agent, Stripe built a system where Blueprints can be customized per team and per task type. An API migration Blueprint differs fundamentally from a test generation Blueprint. Specialization yields higher quality and lower cost.
Constrained Autonomy
Agents have full autonomy within their Devbox sandbox, but their freedom is constrained at every level: scoped tool subsets, Blueprint-defined subtasks, CI iteration limits, and mandatory human review. Autonomy without constraint is liability. Autonomy with constraint is leverage.
Humans Stay in the Loop (at the Right Point)
Despite full agent autonomy during execution, human code review remains mandatory for every PR. Stripe removes humans from the tedious middle (writing boilerplate, running tests, iterating on lint) but keeps them at the critical gate: reviewing what ships.
Meta-Agentics: Tooling for the Tools
Stripe invested in infrastructure to manage agents themselves — Toolshed, Blueprints, rule file synchronization, devbox pools. The meta-layer (tooling that serves agents, not humans directly) is what enables scale. Without it, each agent is a one-off experiment.

Implications for Engineering Teams

You do not need to be Stripe-sized to apply these lessons. The following principles are scale-independent.

What to Adopt Now
  • Invest in reproducible environments — containerized, fast-provisioning dev environments benefit humans today and agents tomorrow. Docker, Devcontainers, and cloud dev environments (Gitpod, Codespaces) are all stepping stones.
  • Adopt rule files — start writing .cursorrules or CLAUDE.md files for your codebase. They help human developers and AI tools simultaneously. This is the highest-leverage, lowest-cost action available.
  • Build deterministic-first workflows — before giving an agent a task, ask: "What parts of this can be solved with a shell script?" Wrap the deterministic parts in code; use the LLM only for the genuinely ambiguous parts.
  • Cap iteration cycles — set explicit limits on how many times an agent can retry before escalating. Open-ended retry loops waste compute and mask fundamental issues.
  • Curate your tool surface — if using MCP or similar tool protocols, do not expose every tool to every task. Scope tool access to relevance. Fewer tools = better tool selection by the LLM.
What to Watch For
  • Blueprint-style frameworks — expect open-source projects to emerge that offer deterministic + agentic workflow orchestration. This pattern will become a standard architecture.
  • MCP ecosystem maturity — the Model Context Protocol is still early. As more tools publish MCP servers, the "Toolshed" pattern will become accessible to smaller teams.
  • Agent-aware CI/CD — CI systems optimized for agent workflows (selective test runs, auto-fix pipelines, iteration budgets) will become a competitive differentiator for CI platforms.
  • In-house vs. off-the-shelf convergence — as commercial tools incorporate Blueprint-like patterns and enterprise context management, the gap between custom and commercial will narrow.
What to Be Cautious About
  • Do not skip human review — Stripe, processing $1T+ in payments, still requires human review for every agent PR. If they are not comfortable with fully autonomous merging, neither should your team be.
  • Do not over-index on PR volume — 1,300 PRs/week is impressive, but the metric that matters is "correct PRs merged that would not have been written by humans." Volume without quality is technical debt at scale.
  • Do not ignore the investment required — Stripe's system works because of years of prior infrastructure investment (Devboxes, Toolshed, comprehensive test suites). The agent layer is the capstone, not the foundation.
